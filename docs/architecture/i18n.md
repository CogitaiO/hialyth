# Hialyth — localization and language switching

Статус: Proposal v0.2

Документ описывает смену языка интерфейса. Приоритет аудио и субтитров в плеере — отдельная настройка и не входит в этот контур.

## Принятые решения

- Первый релиз — только английский интерфейс. Используется нейтральный `en`, без `en_US`.
- Русский язык добавляется после первого релиза. Инфраструктура локализации готова заранее, но `app_ru.arb` и переключатель языка в первый релиз не входят.
- Discord Rich Presence в будущем должен следовать языку интерфейса. В первом релизе он остаётся английским; это не блокирует релиз.
- Отдельный вариант `English (US)` сейчас не добавляем. При необходимости он появится позже как `en_US`.

## Решение

Использовать официальный Flutter-механизм `gen-l10n` и ARB-файлы, а не сторонние пакеты и не самодельные словари.

Почему:

- ключи проверяются при сборке, а не находятся по строковому совпадению во время выполнения;
- поддерживаются ICU-параметры, множественные числа и подстановки;
- `MaterialApp` получает корректные delegates для Material/Cupertino;
- язык можно менять без перезапуска приложения;
- нет сторонней зависимости и собственного формата хранения переводов.

`easy_localization` и подобные пакеты не нужны: они добавляют runtime-загрузку и собственный слой поверх уже существующего механизма Flutter.

## Структура

Первый релиз:

```text
l10n.yaml
lib/l10n/app_en.arb
lib/l10n/generated/app_localizations.dart
lib/core/localization/l10n.dart
```

Будущие файлы, когда появится русский:

```text
lib/l10n/app_ru.arb
lib/core/localization/locale_controller.dart
```

`pubspec.yaml`:

```yaml
dependencies:
  flutter_localizations:
    sdk: flutter
  intl: any

flutter:
  generate: true
```

`l10n.yaml`:

```yaml
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-localization-file: app_localizations.dart
output-class: AppLocalizations
nullable-getter: false
```

Генерация выполняется через `flutter gen-l10n`; сгенерированные файлы не редактируются вручную.

## Первый релиз: только английский

- `app_en.arb` — единственный ARB-файл.
- `AppLocalizations.supportedLocales` содержит только `en`; если системная локаль другая, Flutter откатывается на английский.
- В `MyApp` подключаются delegates и `supportedLocales`, но нет пользовательского переключателя языка.
- `locale` в `MaterialApp` не задаётся: система сама выберет единственную доступную локаль.
- Все UI-строки уже проходят через `context.l10n`. Это и есть готовая инфраструктура: добавление русского позже не потребует переписывать экраны.

```dart
return MaterialApp(
  supportedLocales: AppLocalizations.supportedLocales,
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  // ...
);
```

Переключатель с одним доступным языком не добавляем: это лишний элемент интерфейса.

## Когда добавляем русский

- Добавляем `app_ru.arb` и переводы.
- Заводим `LocaleController` — Riverpod `StateNotifier<Locale?>`.
- `null` означает «как в системе»; `Locale('en')` и `Locale('ru')` — явный выбор.
- Выбор хранится в `SharedPreferences` под ключом `ui_language` (`system`, `en`, `ru`).
- `MyApp` начинает слушать контроллер и передаёт локаль в `MaterialApp`:

```dart
return MaterialApp(
  locale: ref.watch(localeControllerProvider),
  supportedLocales: AppLocalizations.supportedLocales,
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  // ...
);
```

- В `Settings → Appearance` появляется `Interface Language`.
- Варианты: `System`, `English`, `Русский`.
- Смена применяется сразу, без перезапуска; после перезапуска сохраняется.
- Если системная локаль не поддерживается, Flutter откатывается на `en`.

## Правила строк

- В ARB выносятся только пользовательские строки: экраны, диалоги, tooltip, snackbar, пустые состояния, подписи accessibility.
- Логи, технические исключения, диагностика API и сообщения для разработчика остаются на английском. Их не нужно переводить при смене языка.
- Названия аниме, имена файлов, пути, кодеки и идентификаторы дорожек не локализуются.
- Ключи должны быть смысловыми (`libraryFilterWatching`, `playerSkipOpening`), а не повторять английский текст.
- Для счётчиков и времени используются ICU-параметры и `plural`, а не склейка строк:

```json
"episodeCount": "{count, plural, =1{1 episode} other{{count} episodes}}",
"watchedOfTotal": "{watched} of {total} watched"
```

- Даты и числа форматируются через `intl` с текущей локалью.
- Ошибки, которые показывает UI, локализуются на уровне presentation; объекты ошибок и стек остаются техническими.
- Discord Rich Presence: в будущем следует языку интерфейса. В первом релизе остаётся английским. Когда дойдём до локализации, готовые подписи нужно передавать из presentation-слоя, а не вызывать локализацию внутри провайдера.

## План миграции

1. Добавить `flutter_localizations`, `intl`, `l10n.yaml` и `app_en.arb`.
2. Завести `context.l10n`, подключить delegates и `supportedLocales` в `MyApp`.
3. Выносить строки поэкранно: Library → Details → Player → Settings → диалоги.
4. Добавить тесты для английской локали и проверить, что все ключи находятся в ARB.
5. После первого релиза добавить `app_ru.arb`.
6. Затем добавить `LocaleController`, сохранение выбора и переключатель в настройках.
7. Discord RPC и при необходимости `en_US` добавить отдельными шагами позже.

## Тестирование

- Первый релиз: `AppLocalizations.supportedLocales` содержит `en`.
- После добавления русского: `supportedLocales` содержит `en` и `ru`.
- Widget-тест переключения языка: меняем локаль, проверяем заголовок/пункт меню без перезапуска.
- Тест сохранения выбора в `SharedPreferences` — после появления переключателя.
- Golden-тесты ключевых экранов: сначала `en`, после добавления русского — обе локали.
- Проверка, что в ARB нет пустых значений и ключи совпадают между локалями.
